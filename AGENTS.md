# XrOS — Правила разработки для AI-агента

Ты работаешь над репозиторием **XrOS** — настольного дистрибутива на базе Arch Linux (KDE Plasma, GRUB UEFI, подписанный репозиторий `[xros]`). Пиши код, скрипты и конфиги так, как это делает опытный мейнтейнер Arch Linux вручную.

## Жёсткие запреты
- **Никаких нейросетей и AI-зависимостей** в коде, пакетах, утилитах и сервисах XrOS.
- **Никакого «AI slop»**:
  - Не пиши очевидные комментарии, пересказывающие каждую строчку (комментируй только неочевидные системные детали и обходы багов).
  - Не создавай лишних абстракций, обёрток и одноразовых хелперов.
  - Не трогай GPG-ключи (`xros-gpg-prod/`, `xros-gpg-test/`), манифесты подписей и готовые пакеты в `repo/xros/os/x86_64/` без прямой команды.
- **Соблюдай дизайн-код XrOS**: чёрный металлический X с фиолетовым неоном (акцент `#8B00FF`, второй акцент `#B66AFF`, фон `#08080D` / `#111018`).

## Архитектура и стандарты репозитория
- `profile/` — профиль `mkarchiso` (загрузчик только GRUB, UEFI). Держи списки пакетов минималистичными и отсортированными.
- `src/` — исходники компонентов (`xros-installer` на Bash + Rust GUI, `xros-welcome` на PyQt6, `xros-cli`).
  - **Bash**: `#!/usr/bin/env bash` + `set -euo pipefail`, обязательная совместимость с `shellcheck`.
  - **Rust**: минимум крейтов в `Cargo.toml`, без `.unwrap()` в продакшн-коде, проброс ошибок через `?`.
  - **Python (PyQt6)**: минимум сторонних зависимостей сверх системных пакетов Arch.
  - **QML**: чистые декларативные биндинги, бизнес-логика только в Rust/Python.
- `packages/` — соблюдай стандарты Arch `PKGBUILD`, проверяй через `namcap`, не оставляй пустых массивов (`groups=()`, `replaces=()`).

## Воркфлоу с Superpowers и Deslop
- При использовании навыков **Superpowers** (`brainstorming`, `writing-plans`, `subagent-driven-development`):
  - В качестве базовой проверки (test baseline) и финальной верификации ветки всегда используй `./scripts/xros-diagnose.sh` и наборы тестов из `scripts/tests/` (а также `shellcheck`, `namcap`, `cargo check` для затронутых компонентов).
  - При планировании задач соблюдай принцип YAGNI: не предлагай новые зависимости в `profile/packages.x86_64` или `Cargo.toml` без явного согласования.
- Перед завершением задачи или созданием коммита обязательно запускай навык **`deslop`** для очистки изменённых файлов.
