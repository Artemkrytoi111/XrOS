# SECURITY-REPORT.md — Безопасность XrOS 1.0 (live-система)

Дата: 10 ноября 2026. Проект: `~/workspace/xros`.
Метод: проверка исходников профиля, скриптов сборки, конфигурации
служб и установленного ПО (аудит 10.11.2026 — 46 проверок, см.
AUDIT-REPORT.md; повторная проверка при пересборке fixed1–fixed4).

## 1. Итог

Критических уязвимостей, внесённых исправлениями fixed1–fixed4,
не обнаружено. Живая система спроектирована как демонстрационная:
автовход без пароля, sudo без пароля — это осознанный выбор для
live-режима (как в Arch releng), а не дефект; установленная система
получает нормального пользователя с паролем через инсталлятор.

- **sudo**: `xros ALL=(ALL) NOPASSWD: ALL` — только в живой системе;

- **Файрвол**: `ufw default deny incoming`, служба `ufw` включена.
- **Права**: исправлен дефект 2770 (см. FIX-REPORT.md §1–2).
  В rootfs fixed4: 0 каталогов 2770, 0 файлов 660 (кроме

- **Репозиторий**: `[xros]` в pacman.conf — `SigLevel = Optional

- **Автоблокировка**: в живой системе отключена (у xros нет

- **Случайные пакеты**: не устанавливались; все пакеты — из

## 3. Остаточные риски (честно)

- **GPG-подпись репозитория отсутствует** (`Optional TrustAll`).
  Риск: подмена пакетов при появлении публичного сервера.
  Митигация: сервера нет (PLACEHOLDER), пакеты ставятся только
  из снимка внутри ISO. Перед публикацией — подписать репозиторий.
- **sudo NOPASSWD в live-режиме**: любой процесс от xros может
  получить root. Это свойство live-системы с автовходом, а не
  баг; физический доступ к live-носителю и так даёт root.
- **Автообновления отключены** (по ТЗ): установленная система
  не получает исправления безопасности автоматически; пользователь
  обновляется вручную (`pacman -Syu` / `xros upgrade`).
- **KWin/plasmashell под TCG**: спин CPU ~65% (см. FIX-REPORT.md);
  это не уязвимость, а производительность в эмуляции.
- **GRUB**: пароль на загрузчик не задан (LUKS/GRUB password —
  не сделано, см. MEMORY.md); физический доступ = доступ к данным
  live-системы (для live-режима нормально).
