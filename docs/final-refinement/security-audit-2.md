## 2. Новые защиты с 2026-11-20

- **R-18 — нечитаемое устройство**: `src/xros-install:479` `xros_device_readable`
  (проба `head -c 512`), `396` `xros_disk_blocked` (код 2, fail-closed),
  `484` `xros_require_disk_free`. Тест `test-raid-block.sh` — 48/0 (CI №27).
- **R-04 — повторная проверка перед wipefs**: проверка диска непосредственно
  перед разрушительной операцией; `mkfs_root` (838) перепроверяет раздел
  перед `mkfs` (843).
- **A-24 — RAID в блоклисте**: `linux_raid_member`, `isw_raid_member`,
  `ddf_raid_member`, `promise_fasttrack_raid_member` + префикс `raid*`
  в движке, Diamond и Rust GUI.

## 3. Открытые вопросы (не новые критические уязвимости)

- **Ротация GPG (P0, заблокировано)**: `packages/xros-keyring/PKGBUILD`
  ждёт `xros-public-new.key` (отпечаток `9E71EDB1…`, SHA-256 `3ffb45e5…`),
  которого нет в git — пакет не собирается из чистого клона. Переходный
  период — до 13.12.2026. Приватный ключ в репозиторий не вносить.
- **Пароли по умолчанию в истории git**: коммиты 2026-11-12 содержат
  пароль `xros` в сообщениях. Запланировано удаление в чистке истории
  (День 2) с отдельной веткой-бэкапом; force-push — только после
  подтверждения.
- **SIGPIPE в `say()` движка**: `say()` пишет через `tee` в stdout; при
  мёртвом GUI обработчик ловушки может погибнуть от SIGPIPE до очистки
  (механизм доказан экспериментом). Закалка — открытая задача.
- **Расхождение бинарей GUI/CLI и A-05**: записанные хэши — эталон;
  исправление — пересборка бинарей под хэши, а не подгонка хэшей.
  Это гигиена цепочки поставок, а не уязвимость в коде.
- **Отсутствует `packages/xros-installer/xros-installer-diamond`**:
  полная сборка пакета из чистого клона падает в `prepare()`.
  На `makepkg --printsrcinfo` не влияет.

## Вердикт

Новых критических проблем в проверенной области не найдено. Все 7
исправлений hardening от 2026-11-20 держатся в текущем коде. Открытые
вопросы выше — известные, отслеживаются; два из них (GPG и чистка истории)
требуют действий владельца.
