## Подтверждено исправным (перепроверено, без изменений)

- **Пароли не попадают в журнал/аргументы**: `say` нигде не печатает
  USERPASS/ROOTPASS (проверено grep); `chpasswd` — только через pipe,
  пароль `%q`-экранирован; `%q` round-trip проверен динамически (T3)
  для паролей с пробелами, `$`, backtick, кавычками, `;`, `*`, `$(…)`,
  табом. Пароль с переводом строки: `%q` сохраняет его, но `chpasswd`
  читает построчно — такой пароль даст жёсткую ошибку chpasswd
  (стоп установки), а не тихую неверную установку; GUI (singleline)
  и dialog (passwordbox) перевод строки не дают вовсе.
- **Живой NOPASSWD не попадает в установленную систему** (`live-xros`
  удаляется; `%wheel … ALL`, пароль обязателен) — без изменений.
- **GRUB**: `grub-install` (оба target) и `grub-mkconfig` — с явными
  ошибками; финальные проверки (ядро, initramfs, grub.cfg, fstab,
  пользователь, hostname, DM, тема, EFI-файл/MBR-код) — на месте.
- **Сигналы**: trap HUP/TERM/INT + сторож родителя + PDEATHSIG/setsid
  в GUI — без изменений (регрессионный тест `test-child-process.sh`:
  33/33 PASS).
- **machine-id** (удаляется + пересоздаётся в chroot), **resolv.conf**
  (удаляется после сетевых операций), **живые следы** (rsync-исключения
  ssh_host_*/gnupg, удаление autologin/welcome/xros) — без изменений.
- **customize_airootfs.sh**: пароли заблокированы, sshd выключен, ufw
  включён, NOPASSWD только для живой системы; утечек нет.
- **Автообновления выключены** (репозиторий без подписи, `xros.example` —
  PLACEHOLDER) — без изменений.

## Оставшиеся риски и ограничения (честные SKIP)

1. **Полный путь identity на реальном диске (T2c) не проверен здесь** —
   в песочнице нет блочных устройств. Нужен прогон
   `test-installer-security.sh` в живой системе/QEMU, где `/dev/sdX`
   есть (тест сам найдёт первый блочный диск и проверит стабильность
   идентификатора и ловлю подмены).
2. **GUI не пересобран и не проверен `cargo check`** (нет cargo на
   хосте) — только чтение кода; пересборка обязательна до ISO
   (см. выше).
3. **Полная установка до конца в QEMU не проверена** (как и раньше):
   реальное поведение новых проверок на живом железе/в VM —
   перетыкание USB между выбором и разметкой, смонтированный раздел
   цели, обрыв на `sgdisk`/`rsync` — только после сборки ISO.
4. **`wipefs -a … || true` оставлен без жёсткой проверки сознательно**:
   его падение не фатально — таблицу перепишет `sgdisk --zap-all`
   (уже с проверкой). Если `sgdisk` тоже недоступен — установка
   честно падает на его проверке.
5. **Пароль с переводом строки** — даст ошибку `chpasswd` и стоп
   установки (не тихую неверную установку). В GUI/dialog такой пароль
   ввести нельзя; через правку конфига вручную — только стоп.
6. **Диагностика 165→169 / SKIP 13→11**: дельта объясняется не только
   этим аудитом — на этом хосте доступен `grub-script-check`
   (+2 PASS) и в проект между замерами вносились чужие правки
   (ветка DE=none). Регрессий нет: FAIL=0 до и после.
7. **Сторож `xros_watchdog`**: при недоступности `ps` (`cur` пуст)
   он убивает группу — `ps` в живой системе практически не падает;
   оставлено как есть (пренебрежимо мало).
8. **LUKS/пароль GRUB, Secure Boot, GPG-подпись репозитория,
   публичный хостинг репозитория** — отдельные задачи, как и раньше.
