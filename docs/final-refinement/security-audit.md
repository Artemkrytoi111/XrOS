# Аудит безопасности установщика (повторный, координатор, 2026-11-10)

Проверено чтением: `src/xros-install` (573 строки, целиком), `src/xros-install-gui-rs/src/install.rs` (целиком),
`profile/airootfs/root/customize_airootfs.sh` (фрагменты), сверка `src/*` vs `profile/airootfs/usr/local/bin/*`.

## Подтверждено исправным

- **Живой NOPASSWD не попадает в установленную систему**: создаётся только в
  `customize_airootfs.sh:55-56` (`xros ALL=(ALL) NOPASSWD: ALL`, 440), движок удаляет
  `$TARGET/etc/sudoers.d/live-xros` (строка 359). Установленная система: `%wheel ALL=(ALL:ALL) ALL`, пароль обязателен.
- **Пароли не попадают в журнал**: конфиг GUI — 0600 с момента создания (`install.rs`, OpenOptionsExt::mode + set_permissions),
  движок удаляет конфиг после чтения (`rm -f "$CONF"`), umask 077, журнал 600. Пароли в chroot-heredoc — `%q`-экранированы,
  heredoc идёт в stdin chroot-bash, в лог не пишется; `chpasswd` получает пароль через pipe, не через argv.
- **Защита от форматирования диска с ISO**: в неинтерактивном режиме — проверка ISODISK и для erase, и для manual
  (PKNAME корня), плюс повторная проверка перед разметкой в `run_install`; в интерактивном режиме ISO-диск исключён
  из меню lsblk и есть отдельная проверка + подтверждение «Да, стереть $DISK».
- **Разрушительные действия с подтверждением**: интерактивный режим — явный yesno перед стиранием; ручной режим —
  разделы уже выбраны и подтверждены в GUI.
- **Живые следы не копируются**: rsync исключает `/etc/ssh/ssh_host_*`, `/etc/pacman.d/gnupg/*`, `/tmp/*`, `/run/*`;
  движок удаляет machine-id, resolv.conf (после сетевых операций), автовход SDDM, автостарт приветствия,
  живого пользователя xros, `customize_airootfs.sh`.
- **GRUB install с явными ошибками**: `grub-install`/`grub-mkconfig` с `|| { say ОШИБКА; exit 1 }`,
  финальная проверка (ядро, initramfs, grub.cfg, fstab, пользователь, hostname, DM, тема, EFI-файл/MBR-код).
- **Автообновления выключены**: движок намеренно НЕ включает `xros-update.timer`, комментарий + ссылка на repo/README.md.
- **Интерактивный режим**: `run_install | dialog --gauge` под `set -o pipefail` — код ошибки движка доходит до проверки RC.
- **Синхронность**: `src/xros-install`, `src/xros-welcome`, `src/xros-welcome-gui` побайтово совпадают
  с копиями в `profile/airootfs/usr/local/bin/` (diff -q, 2026-11-10).

## Найдено (передано в работу / на проверку)

1. **Нет trap на SIGINT/SIGTERM/SIGHUP/EXIT в движке** — при убийстве движка монтирования в `$TARGET`
   остаются, установка обрывается грязно. → В работе у агента child-process (задача 3): trap + cleanup
   (umount -R, удаление временных файлов), идемпотентность cleanup. Статус: проверить после его сдачи.
2. **GUI не защищает дочерний процесс от своей аварийной смерти**: в `install.rs` нет `PR_SET_PDEATHSIG`,
   нет process group, нет `child.kill()` при выходе. Подтверждено чтением кода. → В работе у агента
   child-process (задача 3), включая тесты `scripts/tests/test-child-process.sh`.
3. **Конфиг с паролями остаётся в /tmp, если spawn движка упал**: `write_conf` создаёт `/tmp/xros-install.conf`,
   удаляет его только движок после чтения. Если `Command::spawn()` вернёт ошибку — файл с паролями остаётся.
   → Исправить в `install.rs`: при ошибке spawn удалять CONF (или писать конфиг только после успешного spawn —
   невозможно, конфиг нужен до запуска; значит — удаление в ветке ошибки).
4. **GRUB_COLOR_HIGHLIGHT="white/cyan"** в `/etc/default/grub` установленной системы (`src/xros-install:381`) —
   cyan противоречит палитре XrOS (тема theme.txt переопределяет цвета, но fallback — cyan).
   → Мелкий фикс координатора при слиянии: `white/magenta`, как в живом `profile/grub/grub.cfg`.
5. **ISODISK-пусто — проверки молчат**: если `/run/archiso/bootmnt` недоступен (нештатная загрузка, например
   Ventoy без archiso-метки), `ISODISK` пуст и все проверки «не ставить на диск с ISO» пропускаются.
   → Задокументировать как ограничение; при пустом ISODISK в неинтерактивном режиме писать предупреждение в журнал
   (не блокировать установку — живой системы без bootmnt не бывает в штатном сценарии).
6. **`swapoff -a` в `run_install`** — выключает весь swap живой системы до разметки; безвредно в Live, но стоит
   комментария в коде (почему это безопасно). Неисправленная косметика, не блокирует.
7. **Приветствие запускается ТРЕМЯ механизмами одновременно**: systemd user service + xdg/autostart .desktop +
   `.xprofile` (flock — только страховка от дублей). → В работе у агента welcome-wayland (задача 4):
   оставить один основной механизм.
